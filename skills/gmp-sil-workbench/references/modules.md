# 独立模块的增加、修改与移除

## 先找到正确的接入位置

独立模块应能说明自身的输入、输出、状态、调用频率和退出行为。独立不等于完全没有依赖，而是依赖集中、方向明确，主工程仍负责统一运行。新增模块前先查当前 GMP 组件及项目已有组件，不由功能名称直接判断需要从零实现。

| 需求 | 优先归属与接法 | 核心检查 |
|---|---|---|
| 给定或轨迹组件 | 复用已有组件；用户层在现有参考入口提交 | 不绕过参考限幅与模式准入；区分生成值、限速值、控制器参考 |
| 控制或补偿组件 | 独立实现和必要适配；由原控制调度选择调用 | 与原状态、限幅、前馈、调制和实际提交量衔接 |
| 定位、参数辨识 | 完整组件；用户状态机发请求和查询结果 | 角度/电流写入先后、成功/失败/超时、旧值恢复 |
| VOFA 或记录扩展 | 通信组件或现有诊断模块；板级仅提供收发 | 帧格式、容量、频率、并发快照、旧通道兼容 |
| 新传感器、板卡、外设后端 | board 与 xplt；公共控制通过端口读取 | 单位、方向、量化、采样时刻、故障及禁能语义 |
| 仅新增益或新权重 | 现有控制族参数区 | 不复制算法、整个 suite 或电机模型 |

公共数据端口优先使用 GMP 已有 ADC、位置/速度编码器等接口对象，通过当前版本的 attach/set/get API 连接。不要只为绕开一个接口，就让算法直接读寄存器、UDP buffer 或另一组件的私有状态；确需新增观察量时，通过清晰的只读输出暴露。

## 把模块契约写具体

根据实际需求，在现有实现说明或代码接口旁确定：

- **输入与输出**：单位、有效范围、是否本拍新值、无效输入如何处理；谁最终提交参考/电压/PWM，其他逻辑何时让出。
- **配置与状态**：运行可改设置、编译参数和内部状态分开；状态有唯一持有者。GMP 现有积分器足够时不要另存一份平行积分状态。
- **生命周期**：初始化、开始、每拍或慢拍更新、正常退出、禁止/故障退出、复位、再次进入。按需要提供 init/reset/step/track/commit，而不是为了形式凑齐所有函数。
- **更新时序**：使用调用点的实际频率计算系数；读取前/更新后状态、先提交后记忆都需明确。不要在两个平台分别实现调度。
- **运行更改**：成组校验有限值、边界和组合约束；说明逐字段写入是否可能产生合法中间组合，是否需要快照、序号或确认机制。
- **关闭与移除**：运行禁用的输出/状态语义、编译裁剪范围、依赖和所有调用者。运行关闭不等于没有链接或执行负担。

输出只有一个负责者。轨迹组件正在连续提交参考时，普通命令是否抢占、取消还是被覆盖必须明确；不能让两个写入点凭执行先后偶然决定。保护和驱动状态仍有最高的既定门控权，新增模块不得自行重新使能。

## 复用 GMP 的项目封装应有实质内容

例如新增板级测量适配时，平台提供原始输入，公共换算形成具有明确单位的值，再连接到 GMP 测量端口。算法仍通过原端口读取；硬件后端和 SIL 后端复用可共享的换算与有效性规则。实例目录与 preset 分配见[结构示例](preset-example.md)。

模块封装只补足真实需要的边界，例如参数校验、单位转换、有效性或生命周期。若只是无条件转发原函数，不带来依赖隔离或语义澄清，通常不必另建一层。在线参数修改如何生效、禁用后输出保持还是清零，应由当前对象的需求决定。

新增源文件时同时检查 Windows 和目标工程；PC 已链接的库函数在目标工程未必存在。不能用修改生成文件临时解决链接后，就忽略下次生成会覆盖的问题。

## 控制器扩展必须连接真实的非线性行为

仅实现线性公式不足以接入工程。至少核查：

1. **步骤1：确定状态定义与兼容关系。** 数学状态、工程存储量和限幅对象可能不同；声明兼容原实现时，应说明对应关系及其成立条件，不能只比较函数名称或输出范围。
2. **步骤2：确定进入状态。** 依据接管前实际测量、积分、前馈和提交电压初始化；先更新还是先输出按实际代码处理。按更新前电压匹配，却当拍立即更新积分，可能仍出现首拍跳变。
3. **步骤3：确定受限提交。** 区分 raw 请求、限幅后命令、补偿后调制与最终应用量；记录的上一拍输入应是该控制模型定义的实际提交量。处理积分冻结/回算及 d/q 电流、电压余量时保留真实顺序。
4. **步骤4：确定退出与恢复。** 回到 PI 时需要跟踪或映射状态，不能沿用长期冻结的旧积分；禁用、故障、离开速度模式与重复请求分别验证。
5. **步骤5：验证边界。** 未饱和等价、首拍匹配、长期闭环和强限幅是不同条件。无扰切换只在已证明且状态可实现的范围内成立。

继续使用现有公共输出链。新控制器不直接越过电流/电压限幅、死区补偿、调制或板级门控。若研究确需改变其中一项，把它作为显式算法变化记录并验证，不能伪称只换了增益。

## 可选组件要在完整依赖上关闭

0/1 数值型宏用 `#if USER_HAS_...`，不能以 `#ifdef` 判断是否开启。裁剪包括类型/对象、源码、初始化、周期调用、命令分支、监测字段和链接依赖。用实际构建或符号表检查关闭后不存在残余依赖，不以宏值文本代替。

删除前重新查当前全部调用者、构建项和验证入口。后续功能可能已经复用底层组件；此时只关闭某个用户入口就删底层组件，会破坏其他功能。依赖已经扩大时只关闭目标功能，或按用户要求一并迁移依赖后再删。旧产物、源码快照和原始数据不随活动代码清理而删除。

## 采集和辅助代码也受实时预算约束

控制拍仅做必要的锁存、统计或队列写入，格式化、传输和可延后计算放主循环。新增通道同时核对板级缓冲区、协议、上位机、模型和解析器；改变一端通道数不能视为完成。

对 ISR 与主循环共享数据确认一致性，`volatile` 不等于多字段快照原子性。记录控制拍号/样本数、溢出、丢窗和状态；float32 对整数精确表示有范围限制，序号协议需设计回绕和解码。逐拍统计完成不等于原始逐拍数据全部导出。

验证实际目标构建的每个相关翻译单元：优化等级、浮点重结合、RAM 函数放置、Flash 装载和启动复制，检查 MAP/产物和资源余量。平均耗时或稳定平台无法代表首次初始化、参数切换、峰值刷新等最坏拍。PC 功能测试无法给出板端时间；实测超预算要保留失败，不提高预算使其通过。

## 选择能证明本次变化的测试

局部参考模块可先做真实组件长时波形、非法参数、在线更新和启停/故障/接管测试，再做受影响平台的编译链接。控制律/模式/限幅变化再做实际共用 C 闭环及相关 SIL 工况。板级或采样输出变化需接口、模型事件和目标证据。不要为只改说明或无关文件重新启动完整 SIL。

测试运行在隔离输出位置，必要时核对活动源码和原 OUT/MAP 前后哈希。使用新证据目录，不覆盖旧结果。交付注明这些检查覆盖的范围；未做 UDP、GUI 或实板时直接说明。
