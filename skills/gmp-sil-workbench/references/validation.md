# SIL 验证、差异诊断与证据边界

## 先说明本次要证明什么

迁移问题通常问“同样输入是否仍有同样行为”，控制研究问“给定条件下是否达到规格”，现场诊断问“模型与实测差异支持哪一种解释”。先确定问题，再选测试。用已有有效证据承接未变部分；引用证据时带版本、配置和适用范围。

| 证据层次 | 可以支持 | 不能单独支持 |
|---|---|---|
| 源码/预处理/参数消费者检查 | 有效配置、职责、单位、依赖与连接 | 实际运行、闭环性能、物理时序 |
| Windows/TI 构建与链接 | 对应平台可编译，参数/符号/资源进入产物 | 已下载、GUI 正常、CPU 时间、实板功能 |
| 同输入回放/组件功能 | 相同刺激下状态、输出和生命周期的关系 | 两个独立闭环相同，或真实对象性能 |
| 实际共用 C＋平均/非线性对象 | 已覆盖模型中真实控制路径的闭环与模式行为 | 开关细节、UDP 通道和未知物理效应 |
| 实际生产 EXE＋UDP＋开关 SLX | 所用通信、模型、控制和操作路径的集成运行 | 目标 CPU 时序、实机稳定性和保护电气效果 |
| 独立 SLX/线性模型/离线回放 | 算法解释、理论和实现交叉检查、限定模型预测 | 已执行固件，或实机原因已被确认 |
| 日常入口/GUI 核查 | 实际观察过的打开、选组、启动和操作行为 | 所有界面已人工验收，或闭环数值全通过 |
| 实板采集 | 该板卡/固件/工况下的实际行为 | 未测工况、全局稳定性、唯一物理根因 |

这里把源码形式和对象模型分开。例如“实际 C SIL”也可能使用平均模型，不能一律当成生产 UDP 开关模型。报告写清执行主体、对象、输入、步长、控制周期和记录频率。

## 让运行对象和配置可确认

开始有意义的动态测试前，核对对应项：

- 活动源码/依赖版本与必要哈希、dirty 改动、所选配置、有效参数、实际 EXE/OUT 与模型。Git 提交号不能替代未提交源码或外部库文件的身份。
- 电机块当前类型实际读取的电阻、电感、磁链、机械参数；板侧 ADC 比例/零偏、编码器线数/计数与方向、PWM 归一化和死区。识别实测、名义、借用和占位数值。
- 启动/给定/负载的确切顺序与时间，真实门控与状态；避免在普通测试夹具中绕开定位、继电器或故障锁存后，再声称生产流程通过。
- 被运行的模型路径、MATLAB 实际加载的库路径、MEX 兼容版本、工作目录和生成的 network 配置。查清是参考模板、活动模型还是临时副本。
- 所需信号确实记录。`simout.mat` 只有 `tout`、日志有收发字节数或进程返回 0，都不足以计算控制性能。

控制律相同但配置宏、更新频率、补偿或模型不同，要单列为不同配置。所需参数缺失时直接记录缺口，不从同目录其他实验或当前固件反推历史条件。

## 生产 UDP SIL 的准备与运行

按当前项目 README/脚本核实流程，通常为：

1. **步骤1：准备模型和记录。** 打开/加载正确模型和本地依赖，必要时显式导入同源参数，检查有效消费者；在对应目录更新模型生成 `network.json`。模型更新阶段是否触发通信要以当前实现为准。
2. **步骤2：构建并核对控制程序。** 选实际参数对应配置，明确 EXE 路径、哈希和工作目录。工作目录需能读取刚生成的网络配置，不能由 EXE 所在目录推定。
3. **步骤3：启动并建立通信。** 按该项目已验证的顺序启动控制程序与仿真；等待真实就绪/握手。不要把固定等待几秒或“进程存在”当成连接完成。
4. **步骤4：通过原入口驱动。** 默认禁能，按已定义的继电器、Ready、定位、使能、给定流程操作；面板命令的值/命令先设置，序号最后提交。是否可省略定位由当前配置决定。
5. **步骤5：确认完整结束。** 保存预期时长、末拍、退出状态、故障和波形；超时结果标为部分运行。再次运行需要清楚的初始化，通常新建控制程序进程，避免继承上一轮状态。

多实例运行时使用独立端口/工作目录或现有互斥机制。不要对用户 MATLAB/CCS/VS 进程做全局终止；只管理本次创建且身份明确的进程。本机通信有问题先查实际绑定、端口、方向、报文字节及会话，不盲目改防火墙或重装全局库。

原始启动文档可能描述“模型先运行超时后再启动控制器”，早期脚本也可能自动挑第一个 EXE；这些不是通用正确做法。对当前工程使用已经验证的专用入口，并单独确认它实际启动了什么。

## 通信与数值接口怎样查

UDP 收发端口命名有 host/controller 视角差异，应记录两端实际 bind/send，不只对照字段名。核对结构体字段顺序、宽度、对齐、端序、数组长度与 Simulink pack/unpack；`#pragma pack(1)` 是特定协议选项，不能看到错位就无条件添加。

按已知输入做比例/方向/零偏/量化/截顶测试，检查控制器看到的原始输入和物理量。区分物理相电流、dq 电流、过滤反馈、目标电流和原始 ADC。测量与控制类型转换只发生在明确边界，不在多个层重复换算。

新监测通道应注明采样时刻、数据单位、发布频率和缺帧规则。抽点仅用于画图时，指标仍使用指定完整数据；若只有低采样导出，不能推断未记录的瞬时峰值或逐拍首值。

## 同输入回放与闭环比较分开做

保持行为的迁移先冻结一份原始输入序列，将同一 ADC、QEP、命令与故障历史送入两份实际实现。按阶段比较换算量、参考、积分、前馈、限幅、调制/CMP 和离散状态，寻找第一处不同。用两边各自的输入历史分别重放，可避免只验证一个闭环轨迹。

两个独立闭环有反馈，早期一计数 PWM 差异可能改变后续 ADC/QEP 和索引时间，后续峰值因此不同。不能把独立闭环差异直接当同输入算法误差，也不能凭一个浮点反例证明整个闭环差异都已定因。保留原阈值，分别呈现功能、逐拍一致性和性能指标。

独立框图与实际 C 比较要统一对象、参数、参考、使能及已知命令生效拍。为对照对齐输入的延迟留在测试夹具，不能加进生产控制器来“使曲线重合”。不适用的状态通道使用明确的缺失值，不能伪造一个通过状态。

## 物理时序与模型精度需要单独证据

先由寄存器、数据手册和调用链形成时序假设，再用模型事件或实测核对：PWM 触发 → ADC 采样窗口/顺序转换 → 结果可读 → ISR/计算 → CMP 写入 → shadow 加载 → 输出。标出模型忽略的共同延迟、模拟建立、CPU 执行和同步传播。

同一次 SOCA 不等于多通道同时采样；TBPHS=0 不等于板上边沿绝对同时；控制 ISR 频率、算法分频、记录频率和仿真积分步长各自独立。改变开关仿真步长不得悄悄改变控制频率。物理积分步长应按问题做收敛或事件核查，不能仅缩小一次就宣布误差已解释。

模型已有 shadow 加载延迟后，不能再靠通用 UnitDelay 重复加一拍。角度提前是控制补偿，不能与物理执行延迟混为一谈。物理功率级与补偿公式参数也要分开；不能为配合结果改硬件比例或任意拟合损耗。

## 反馈迭代以证据驱动

失败先按链路分类：构建/依赖、选择/配置、通信、接口/单位、时序、控制实现、对象模型、性能/判据。只改有证据关联的因素；不要遇到通信超时就调 PI，或控制不能达到目标就先加经验角度补偿。

开始较大自动搜索时先设有限轮数、参数边界、目标与停止条件，保留每轮版本、失败日志、指标和回退点。测试阈值是验收规格，不能列为自动调参变量。正常工程修复不要求每一步重问许可。

达到目标即可收尾；触及授权/参数边界、同类失败重复且无新证据、缺少外部条件或已达约定预算时，停止该迭代路径，交代已知原因与下一项能区分假设的证据。不要无限改参或反复整套重跑。若新缺陷表明当前方案无效，保留缺陷版本，停止无意义的大矩阵，先修复并验证对应契约。

## 报告与资料收尾

在已有轮次/报告中记录参数组、控制器、对象/SLX 分支、固件与源码身份、工况、记录窗口、指标单位/容差、通过/失败/未测和证据路径。区分计算、预测、回放、实际 C、生产 UDP、实测和因果解释。程序化后台检查不冒称人工目视验收。

保留原始数据、缺帧、失败和原判据；不得把全程时间跨度写成连续采集。对齐波形时交代依据，图前列曲线身份和原始来源，图后解释支持的判断。新增或重绘图时同步更新使用者项目已有的图目和生成器，不另建重复入口。对外发布只包含经授权的材料，按[公开内容边界](publication.md)核查。
