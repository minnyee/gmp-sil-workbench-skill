# GMP 的优势及融合取舍

## 优势来自可复用的工程边界

GMP 的价值是把控制算法、运行调度和平台输入输出连接成可以重复使用的体系。`ctl/component` 提供控制和数学组件，suite 提供实际组合与调度范例，Core/CSP 提供基础服务和平台支持，`xplt` 把用户平台接入框架。同一控制源码可以由目标编译器和 PC 编译器分别构建，SIL 再把 PC 控制程序接到对象模型。组件与接口被保留下来，后续新算法、换板和验证才不必重新搭一套工程。

这不是“所有代码都藏进库里”。用户已有工程中已验证的启动、采样、保护、通信、定位和状态转换，是融合必须保留或明确替换的工程资产。原工程提供行为基线，GMP 提供可复用结构，两者需要逐项对应。

| GMP 能力 | 工程收益 | 维持收益所需条件 |
|---|---|---|
| CTL 对象、数学和控制组件 | 可以复用 FOC、机械环、测速、调制、信号发生器等 | 真正使用对象/接口并核对语义，不能只重命名旧函数 |
| suite 调度和平台接口 | 一份控制逻辑连接 TI 板端和 Windows SIL | 真实构建引用同一份源；寄存器、UDP 和平台启动不进入算法内核 |
| 组件化扩展 | 外设适配、补偿、定位和通信等功能可分别维护 | 参数、状态、内部适配和关闭依赖集中；用户层只负责组合与调度 |
| 配置与实现分离 | 同族参数对照不需复制算法和工程 | 选表能追到编译产物，模型实际消费者同步；配置不是多份活动源码 |
| 实际 C 与对象模型闭环 | 在上板前检查真实实现、模式、限幅和异常路径 | 使用真实调用链；对象模型覆盖范围和目标机差异明确 |
| 分层验证 | 可把迁移错误、接口错误、模型差异和性能不足分开 | 保留同输入回放、独立闭环、目标构建与实板的不同结论 |

## 复用的顺序与必要例外

已有工程先复用当前 suite 和组件，判断仅改参数是否足够；功能不足时寻找 GMP 中匹配组件，再做项目内适配或新增独立组件；只有调用结构、对象或生命周期根本不匹配，才考虑更换 suite 或重组。这个顺序是工程决策依据，不要求把不合适的组件强行套入。

库组件已能表达的功能，优先复用。例如测量接口复用 GMP 对应端口，项目板包提供原始采样和必要换算。GMP 没有所需功能时，可以新增独立组件；仍通过现有测量、调度、限幅和输出接口使用它，避免另造一个顶层控制框架。

“适配”允许对接口、状态或非线性行为做必要处理。新旧 PI 的参数形式、积分坐标或限幅位置不同，直接复制数字可能改变功能；必须解释变换和非等价范围。若严格逐位一致与保留新版原生实现不能兼得，应呈现差异、原判据和选用理由，不能偷偷改算法、降低标准，也不为数值表象人为加入旧版无意义残留。

## 层级正确比目录看起来整齐更重要

公共控制应属于公共源码区域，板级初始化与寄存器操作属于平台板包，xplt 负责连接，用户层负责编排，组件内部持有自身算法和状态。不同 GMP 版本可能用 `src` 或 `implement/common`；保留当前工程已有结构，按职责判断，不机械改成同一目录名。

新增一个目录、转发函数或宏，必须对应清晰的职责、依赖隔离或配置需求。不为“架构完整”重复建立 common/runtime/telemetry，不给每个参数头再套一层只转发的文件，不把一项完整功能拆散到多个无关层。薄适配也不是禁止所有转换：单位、类型和端口转换正是适配的职责，但控制律和板级寄存器不应藏在其中。

唯一活动源码不排斥必要的分支、冻结版本和测试副本。独立算法、物理对象或不可变证据可有明确分支；同一算法仅换增益优先参数化。区分有来源、有用途、有验证范围的分支，与不知哪份才生效的重复工程。

## 同代码验证保留什么，仍缺什么

共用 C 减少“仿真实现一套、固件实现另一套”的偏差，能检查实际状态、限幅、保护准入和数值运算。这要求实际链接的是同一实现，测试没有用简化替身替代关键函数，构建宏和执行频率也对应。

它不自动涵盖目标 CPU 数值细节、优化、Flash/RAM 执行速度、IRQ 延迟、采样建立、PWM 加载截止、功率器件损耗和真实传感器。SIL 对象越详细，可回答的问题越多，但建模假设也越需要可验证来源。平均模型可用于早期算法和状态测试，开关模型可核对 PWM/ADC 细节，实板仍负责确认真实物理行为。

独立 SLX 控制器有不同用途：帮助解释算法并与 C 实现交叉检查。两者一致可能共同实现了错误公式，因此还需目标可达、物理限制和已知退化关系等独立判据。工程效率来自选对验证层次，而非每次运行最多测试。

## 可迁移原则与本地约定

本文件的分层、单一状态归属、实际接口核验和证据边界可用于不同 GMP 工程。目录位置、参数编号、工具名、电机、控制频率和记录方式由使用者在[项目上下文](project-context.md)中确认，不能写成 GMP 的普遍要求。对尚未验证的控制对象、平台或 suite 重新核对支持情况，不据目录存在承诺已支持。
