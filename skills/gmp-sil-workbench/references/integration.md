# 新建工程与融合已有工程

## 先建立三方对应

已有工程融合以三方对照为主线：用户已经验证的参考工程、所选 GMP 版本与 suite、当前活动实现。先确认用户要保留的是功能、数值、物理时序、操作协议还是其中一部分；未给出容差时先定位原判据，确需新增判据再明确说明。

在现有记录内维护必要清单，不另建平行管理文档：

| 功能或配置 | 参考来源 | GMP 对象/接口 | 当前文件与调用点 | 处理方式 | 验证 |
|---|---|---|---|---|---|
| 启动、控制、状态、采样、保护、通信、定位等实际条目 | 文件/函数及有效配置 | 被复用的真实对象 | 当前路径、启用条件、频率 | 保留/适配/新增/关闭/有意改变 | 同输入、状态、闭环、目标构建或待实测 |

包括默认关闭的可选功能。代码存在、预处理后编入、链接保留、运行时调用、实板验证是不同状态。记录编译宏和调用证据，不能由 suite 名称或函数存在推定已经运行。

新建工程没有用户行为基线时，检查 suite 自身示例、Build Level 的实际定义与默认启停路径，确认适合后在工作副本建立工程；不修改上游示例。已有工程则直接沿用活动源，不调用创建命令重新覆盖它。

## 按责任安放代码

| 对象 | 应承担的职责 | 需防止的越界 |
|---|---|---|
| Core/CSP 与上游 CTL | 已有基础服务、平台能力与通用组件 | 用项目需求直接改写整个上游库 |
| suite 公共 `ctl_main` | 控制对象、初始化、调度及必要接入点 | 散放寄存器、板级换算、协议解析，或旁路原生控制对象 |
| 公共 `user` | 本项目状态、命令、运行准入、控制族选择和组件编排 | 再建一套与 suite 竞争的调度或使能状态机 |
| 公共 `components` | 完整功能的算法、状态、参数接口和内部适配 | 把定位/VOFA/死区实现拆散进 board 与业务层 |
| `preset`/既有配置区 | 板卡、功率器件、电机和控制器参数；统一映射 | 计算步骤写入参数表，多处保存独立活动值 |
| 平台 `board`/BSP | 初始化、寄存器、采样换算、硬件故障及门控动作 | 板级函数直接操作控制器或协议内部状态 |
| 平台 `xplt` | GMP 回调与实际硬件/SIL 缓冲区的薄连接 | 复制控制算法，或绕过已有换算、保护和输出门控 |
| tests/tools/verification | 刺激、回放、构建编排、日志和证据 | 测试快捷命令改变生产协议，测试副本成为活动模型 |

保留已验证 BSP 的初始化顺序、SysConfig/外设设置、链接脚本和目标支持。可以保留用户 `main_clean` 一类启动壳：硬件初始化后进入 `gmp_base_entry()`，控制 ISR 调用当前 GMP 框架入口。启动壳的价值是隔离平台启动，不是固定某个文件名或强制另写 main。

硬件与 SIL 必须通过构建引用共用源码。板包中可共享的换算与判据允许供 SIL 使用；寄存器访问需按后端隔离，PC 不引入 TI 寄存器头，目标固件不链接 Windows UDP。不要因为板包包含共享换算，就宣称它已是任意板型通用接口。

## 先还原一拍中真正发生的事

读取有效宏与调用者，再画出实际路径。标准回调模式常见顺序是：

```text
平台采样事件/ISR
  → gmp_base_ctl_step
  → ctl_input_callback：取原始量、换算、保护、编码器和项目输入处理
  → ctl_dispatch：测量更新、控制到期判断、参考、控制律、补偿、调制
  → ctl_output_callback：门控复核、硬件寄存器或 SIL 输出
```

这是核对框架，不是所有版本的固定执行图。Nano framework、PIL、项目分频和显式调度宏可能改变负责者；确认控制状态每拍只推进一次。主循环服务、ISR、慢环、UDP 命令生效和硬件 shadow 加载分别注明执行时刻。不要把主循环调用频率当控制频率。

典型易错顺序：机械环生成参考后再施加定位参考，随后执行 FOC，否则定位电流会被覆盖；补偿发生在既定电压/调制位置，检查原生补偿是否已启用，防止重复；故障先阻断输出，不能等待普通后台调度；控制器禁用清理不能同时抹掉继电器计时或应用状态。

## 接口核对必须到数值和状态

修改对应路径时至少核对以下相关项，不为无关任务全量展开：

| 接口方面 | 核对内容 |
|---|---|
| 类型与计算 | `ctrl_gt`、`parameter_gt`、转换和数学函数在当前平台的定义；float/定点支持、整型宽度、C/C++ 链接、目标 ABI |
| 单位与基值 | SI/pu、A 峰值/RMS、V、机械 rpm/rad/s、电角 rad/turn、极对数、计数/线数、方向和相序 |
| PI 与滤波 | 串联/并联定义；每秒 Ki、每拍系数、积分坐标；积分先后、限幅顺序、抗饱和与复位；滤波系数的实际离散形式 |
| 调制与硬件 | 名义/实测母线归一化、dq/αβ接口、矢量限幅、死区、CMP 范围、整数转换、门控、加载时刻 |
| 时钟与分频 | 基础 ISR、控制执行、速度差分、参考更新、PWM、导出和仿真积分步长分别多大；未到期拍保持什么 |
| 状态与生命周期 | 初始化、启动、定位、运行、禁用、故障、重启和模式切换；积分/滤波/历史输出由谁保存、清零或跟踪 |
| 通信 | 字段顺序、类型、实际字节数、对齐、端序、序号、有效位和锁存时刻；不得因两端字段名相同而省略 |

按当前代码确认实际函数语义，特别是角度、频率、每拍系数和物理单位。声明、注释与实现可能来自不同修订，不能凭注释机械传值。使用 GMP 类型和数学接口不自动保证所有已选组件支持定点；项目明确使用浮点时，不为抽象形式大范围替换已验证算术。

对参考行为保持，先固定同一原始 ADC/QEP/命令输入，比较关键中间量、状态和输出。代数相等不代表有限精度相等；发现差异先追第一处不同，包括运算分组、π常量、量化边界及转换规则。允许的有意差异应明确记录，不能默认改回旧实现或统称浮点误差。

## 参数、模型和产物保持明确对应

选取当前工程的参数权威源，画出“参数头/表 → 预处理选择 → 系数 → 构建产物 → 实际运行”的关系。读取有效宏或编译后值，不能仅检查编辑的文本。具名构建可能覆盖手动 include；Debug/Release 的具体用途由工程定义。运行中的固件不会因电脑改文件自动更新。

模型同步检查实际消费者：有的电机块按当前模式使用 `La`，另一些使用 `dqInductances`；工作区正确而有效字段仍是旧值，同样是错误。检查保存、关闭重开、导入方向和已加载库路径。保持用户已有模型布局、Scope 和人工修改，批量试验使用隔离副本或不落盘的插桩。

变更对象、周期或设计条件后重新判断旧增益的适用性；构建不等于重新执行离线设计。迁移参考与明确改变行为的参数分开登记；参数编号与具体定义遵循当前项目约定。

## 生成与发布只做必要工作

先查生成器读取什么、覆盖哪里、是否仍在构建前自动执行。生成源码是选择的依赖输出，不是第二套上游，也不是随意手改的长期源。优先修改实际选择配置或项目适配；必要生成后补丁需可重复、带前置版本检查并验证产物。项目已经直接维护参数时，不恢复停用生成器。

移动目录、SLX 或构建输出后，核对 include/链接资源、相对依赖、工作目录、network 配置及实际运行。一次性建模/整理脚本不能成为日常打开入口。重建到新输出位置保留旧产物身份；发布前复核实际交付版本，不把隔离构建通过自动算作日常入口通过。
