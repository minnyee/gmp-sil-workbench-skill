# GMP 工程融合与 SIL 开发

目标是利用 GMP 的组件、调度、平台接口和同代码验证能力，让用户已有工程可以继续演进。先理解已有实现和用户要保留的行为，再决定复用、适配和新增的范围。工程能运行、架构保持、数值一致、性能达标与实板通过是分别需要证据的结论。

## 按任务读取

只读取本次需要的资料，不把全部历史、完整验收矩阵和本机约定强加给小修改。

| 本次任务 | 读取资料与重点 |
|---|---|
| 理解优势、评审融合方案或首次使用本 skill | [原则与取舍](references/principles.md)：为什么采用 GMP、如何保留优势 |
| 新建工程、迁移已有工程、调整层级或接口 | [工程融合](references/integration.md)：三方对照、实际调用链、数值与时序契约 |
| 增加、更换、关闭或删除独立功能模块 | [组件增量修改](references/modules.md)：状态归属、接入位置、GMP 复用及退出行为 |
| 构建、SIL、差异诊断、比较模型与实际代码 | [验证与诊断](references/validation.md)：证据分层、运行准备、差异定位与停止条件 |

## 先确定工作属于哪一种

1. **步骤1：定位当前对象。** 明确活动工程、GMP 实际版本、用户参考工程、目标平台、参数入口、模型和当前轮次；检查相关 Git 改动。已有工程优先沿用。说明性任务到此可直接分析，不创建工程或启动测试。
2. **步骤2：定义本次变化。** 把用户需求落实到输入、输出、调用位置、执行频率、状态与验收条件。区分保持原行为的迁移、明确改变行为的研究、只改变给定/记录的实验辅助模块。读取当前代码与生效构建配置，不根据文件名或历史说明推定功能。
3. **步骤3：确定最小充分改动。** 已有 suite 内优先使用已有参数与组件；不足时在原边界适配或新增组件。只有新目标确实不适合现有 suite，才选其他 suite 或重组。若工程提供创建命令，先查其能力且只用于新任务；已有任务不重新复制整套工程。
4. **步骤4：实施并保留来源。** 保持唯一公共源码、原有板级职责和 GMP 调度；分别记录保留、适配、新增、停用及有意改变的行为。需要隔离时使用可追溯测试副本，不把副本发展成第二活动工程。
5. **步骤5：按变化选择验证。** 先验证受影响的真实路径，再判断是否需要扩大。参数、控制律、采样/输出时序变化需要相应行为证据；纯文字修改检查内容和链接即可。实际双平台代码变化要检查两个平台受影响的构建和接口。
6. **步骤6：交付可继续维护的结果。** 更新原入口、参数说明和相关轮次；生成内容同步修改实际生成器。说明改了什么、为什么、测试对象与判据、已通过/失败/未测、活动产物和版本；提交、推送及数据保护依该项目规则执行。

## 全程保持的约束

- **GMP 上游作为只读依赖。** 项目适配在用户工程完成；确需库修复时使用项目本地适配或可追溯补丁，并说明版本和影响。不得为修复单一任务静默覆盖上游、全局 Simulink 库或生成源码。
- **一个控制实现，多种平台接口。** 硬件和 SIL 编译同一份控制、状态与可共享组件。平台差异由 board/CSP/xplt 处理；实际支持范围以构建与运行验证为准，不能由“共用 C”推导成跨芯片零适配。
- **保留 GMP 的有效能力。** 继续使用合适的 CTL 类型、端口、对象和算法；不要把旧控制器整体塞进 `ctl_dispatch` 后仅保留 GMP 名称，也不要为了形式统一丢失用户已验证的功能、保护和操作方式。
- **接口包含行为。** 除函数签名外，核对单位、基值、相序、方向、初始化、积分与限幅、更新先后、保持拍、复位和输出门控。每个状态和输出在同一拍只能有明确的负责者。
- **参数来源唯一，执行阶段明确。** 区分设计量、编译后系数、运行可调量、模型快照及固件产物。不得默认 JSON、默认 Debug、同名参数或当前磁盘代码就是实际运行的配置。
- **保留参考行为与研究变化的区别。** 迁移不顺手整定；研究可以改变控制器，但需新配置和对应证据。不得通过改对象、放宽判据、绕过保护或删失败数据使结果“通过”。
- **测试设施不改变产品语义。** 注入、记录、回放和模型包装优先放既有 tests/tools 边界；需要进入实时链的采集只保留必要工作。测试能直接设置内部状态，不代表产品命令允许同样操作。
- **用户授权按实际任务执行。** skill 不额外强制逐步审批，也不授权下载固件、使电机运转或扩大外部操作。默认后台处理；不关闭用户软件，不修改无关文件或清理原始数据。

## 完成前回答

用具体文件、函数、配置和证据回答：复用了哪些 GMP 能力；用户原工程哪些行为保留或有意改变；新增逻辑归属哪里；硬件/SIL 如何引用同一实现；参数与时序如何确认；本次证据证明到哪一层。必要缺口直接说明，不用“编译成功”“波形看起来一致”替代尚未完成的验收。
